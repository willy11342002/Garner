
# 個人知識庫產品 — 架構與商業邏輯
> 最後更新：wireframe 討論階段

---

## 產品定位

**一句話：被動建立的第二大腦。**

用戶不需要主動整理，系統自動把他們感興趣的內容變成可搜尋、可關聯的知識庫。

### 對標競品的差異
| 工具 | 定位 | 弱點 |
|------|------|------|
| NotebookLM | 你餵它，它幫你整理 | 手動上傳、各 Notebook 孤立、無自動關聯 |
| Notion / Obsidian | 自己建架構 | 需要學習成本、要主動維護 |
| **Garner** | 半自動收集 + 自動關聯 + 社交分享 | — |

---

## 內容來源（收集層）

| 來源 | 方式 | 風險 | MVP 優先順序 |
|------|------|------|------------|
| YouTube 長影音 | Chrome Extension 一鍵儲存 | 低，有官方字幕 API | ✅ 第一優先 |
| 網頁文章 | Chrome Extension 自動偵測，抓 og:image | 低，最穩定 | ✅ 第一優先 |
| IG 短影音 | 用戶點「分享」傳網址，第三方解析縮圖 | Meta 隨時可能封鎖 | 第二階段 |

**縮圖抓取方式：**
- YouTube：`https://img.youtube.com/vi/{VIDEO_ID}/maxresdefault.jpg`（免費，不需 API）
- 文章：Open Graph `og:image`
- IG：第三方服務（Apify 等），屬灰色地帶，之後再處理

## 產品架構（六層）

```
收集層：IG分享 / YouTube / 文章爬取
儲存層：原始內容 + 軟刪除狀態機
理解層：AI摘要 + 自動標籤（AI產生，用戶可改）+ Embedding
關聯層：Vector DB 語意連結
查詢層：自然語言搜尋（多模態）
社交層：集合分享 / Fork / 公開探索
```

## 核心功能

### 1. 快速收集
- 最低摩擦：用戶點「分享」或 Chrome Extension 一鍵，後面全自動
- 存入後即時回饋：縮圖 + 摘要 + 自動標籤 + 關聯提示

### 2. 標籤系統
- **AI 自動產生標籤**（零摩擦）
- 用戶可在「最近新增」頁快速批次調整
- 標籤是核心單位，取代傳統分類（一筆內容可有多個標籤）
- 首頁以標籤為列，Netflix 橫向卡片式呈現

### 3. 自動關聯（核心護城河）
- 技術：Vector Database + Embedding（語意相似度）
- 效果：存的內容越多，關聯越豐富，越難離開
- 目標層次：語意關聯（第二層）即可

### 4. 自然語言搜尋（多模態）
搜尋支援五個維度：
- 關鍵字：「京都」
- 語意：「日本傳統文化相關」
- 時間：「三個月前存的」
- 來源：「IG 影片」
- 模糊描述：「那個讓我很想去的地方」

### 5. 資料管理
**資料狀態機：**
```
active → archived → deleted（軟刪除，24hr）→ 排程硬刪除
```
- 刪除需清除：原始內容 + AI摘要 + Embedding向量 + 關聯連結
- 封存：不出現在搜尋結果，但保留資料
- 支援批次操作（多選 → 批次封存／刪除）

### 6. 分享與 Fork（社交層）⭐ 新增
**分享單位：標籤集合（方案 B+C）**

分享方流程：
```
選擇標籤（#京都）→ 預覽該標籤所有內容
→ 全選或手動取消某幾筆（微調）
→ 設定公開 / 連結分享 / 私人
→ 生成分享頁
```

接收方（Fork）流程：
```
看到分享頁 → 預覽所有內容
→ 全選 fork 或手動挑選（進入選擇畫面）
→ 登入／註冊後 fork 進自己的知識庫
→ 標籤自動帶入，可改名
```

**連結三種狀態：**
| 狀態 | 說明 | 用途 |
|------|------|------|
| 私人（預設） | 只有自己看到 | 一般使用 |
| 連結分享 | 知道連結才能看，不被搜尋 | 傳給朋友 |
| 公開 | 任何人可搜尋到 | SEO 流量、冷啟動 |

**重要技術細節：**
- Fork 只複製連結 + 摘要 + 標籤，不複製原始內容
- 儲存成本不會因 fork 倍增
- 公開集合可被 Google 索引 → SEO 自然流量

**成長飛輪：**
```
用戶整理公開集合 → Google 索引 → 新用戶搜尋到
→ Fork 進知識庫 → 順便註冊 → 繼續創造公開集合
```

## 首頁設計

### Hero Section（正中間大圖）
**「今日回顧」**——系統從知識庫挑一筆存了 30 天以上、從未點開的內容
- 每天不一樣，讓人有理由每天打開
- 解決「存了就忘」的核心痛點
- 不需要用戶做任何事

### 列排序演算法（純數學，非 AI）
Reddit / Hacker News 熱度公式：
```javascript
score = (clicks + saves*2 + related*1.5) / Math.pow(hoursSince + 2, 1.8)
```
- 新內容短暫衝到前面
- 常點的標籤維持上方
- 久未碰的標籤慢慢沉底

### 瀏覽模式（可切換）
- **首頁**：Netflix 卡片式，以標籤為列，含 Hero Section
- **最近新增**：清單式，快速調整標籤、批次管理
- **知識地圖**：節點連線，探索模式，查看關聯
- **探索**：瀏覽他人公開集合，一鍵 Fork

## Magic Moment（關鍵體驗）

> 用戶存了一個月的東西，某天隨口問了一句話，
> 系統把他自己都忘記存過的東西找出來，
> 還連結到另一個他完全沒想到有關係的內容。
> 「咦？它怎麼知道？」

### 撐過前兩週的設計原則
1. **即時回饋**：每次存入馬上顯示摘要 + 標籤 + 關聯提示
2. **容錯搜尋**：模糊描述也能找到
3. **今日回顧**：每天打開都有新東西
4. **Fork 冷啟動**：第一天就可以 fork 別人的集合，知識庫不空白

## 商業模式

### 定價
| 方案 | 價格 | 內容 |
|------|------|------|
| 免費版 | $0 | 每月限制查詢次數（約50次） |
| 付費版 | $9–15/月 | 無限查詢 + 更多儲存空間 |

**付費牆位置：** 自動關聯體驗到之後——用戶感受到魔法，自然付費。

### 成本結構（每活躍用戶/月）
- Embedding（存入）：極低，可忽略
- LLM 呼叫（查詢）：$5–20
- Vector DB 儲存：初期免費額度夠用
- **毛利率目標：60–70%**

### 獲利時間軸
```
0–3個月：開發 MVP
3–6個月：上線，找前100個用戶
6–12個月：驗證付費轉換率
12個月後：轉換率 > 5% → 正現金流
```
